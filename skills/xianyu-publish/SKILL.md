# 闲鱼待上架队列

工作台：http://127.0.0.1:8766/
代码与数据库：`/Users/wanghongjie/Documents/Codex/2026-10-28/wo/outputs/sam-three-sellers/`
启动：在该目录运行 `python3 server.py --port 8766`。不要使用静态 http.server，队列需要服务端接口。

## 职责与上架资料

本 skill 只执行上架，不重新选品，不制作营销文案或设计商品图。商品采集和资料整理由 `xianyu-archive` 负责。
取件后读取 `<商品库目录>/listing-packages/<product_id>/listing.json`，格式见 [references/listing-package.md](references/listing-package.md)。资料单必须明确正文、图片顺序、SKU对应价格、运费、来源与缺口；执行用的版本确定后保存到本次批次目录。
旧档案没有资料单时，先按采集建档 skill 补成资料单，不能把现有 catalog.description 中的“展开”、服务提示和属性控件当正文。不自动改变用户选定的商品。缺信息时可以仅对当前商品补采，并同步来源档案及资料单；不扩展为新一轮选品。
默认原样上架；只有用户明确要求内容制作才生成或改写文案、图片，定稿后再更新资料单执行，不强制三版标题或风格选择。

## 取件与状态

用户指定 N（正整数）；未指定时先询问数量，不自行决定批次。
GET `/api/listing-queue` 返回 `items`，服务端已经按 `added_at ASC, queue_id ASC` 排序。
仅从状态为 **未上架** 的条目取前 N 件；不足 N 件时准备所有剩余件并报告实际数量。默认页面同时展示未上架、待上架，取件不能把待上架重复纳入。
每项的 `product` 是原商品档案，含 product_id、url、description、price_detail、shipping 等。
队列是 `catalog.sqlite3` 的 `listing_queue` 表；不要改商品库排序或为凑够 N 自动加入商品。

状态含义：
- 未上架：用户已加入，尚未完成上架页面填写。
- 待上架：页面已填写完整，并保留给用户审阅和点击发布。
- 已上架：由用户发布后，在工作台手动点击“标记已上架”。本 skill 不将商品标记为已上架。
移出列表只删队列条目，原商品档案保留。重新加入重新计时，初始未上架。

## 填写规则

通过本会话提供的浏览器工具读取原商品页与操作已登录的闲鱼发布页面。使用浏览器工具提供的可见 UI 与支持的上传/下载接口，不调用平台私有接口。
访问闲鱼页面时执行强制节流：任意两个闲鱼页面访问、导航或刷新之间至少间隔 10 秒；搜索页、原商品详情页、卖家页、发布页、重定向和失败页面都计入访问。全程串行，不并发打开多个闲鱼页面，也不通过多个标签页、请求或工具绕过间隔。未满足 10 秒时必须等待；出现验证码、风控、访问限制或账号异常立即停止平台操作。
每件保留一个独立发布标签页，不点击发布。可用时标记标签页为 deliverable 防止回收。
**标题、商品描述按原商品信息原样填写，不改写、不润色、不摘要、不增加营销句。** 以原商品描述区域为准，不混入卖家昵称、浏览数等页面控件文字；如存档混入控件文本，回原页确认。平台只有描述字段时照录完整原文，不另造标题。

### 空格、加号与编码

描述取自原商品可见正文，不从搜索词、URL 参数或表单编码字符串生成文案。原文空格必须保留为空格，不转换成 `+`、`%20` 或字面转义字符。
遇到疑似空格变成 `+` 时，对照原商品正文截图和可见 DOM 文本，再判断来源：原商品本身显示的加号保留（例如 `26cm+30cm` 或卖家使用的 `原装正品+未拆封`）；只修正经对照确认由采集、编码或填写引入的字符变化。不得全局把所有 `+` 替换为空格，也不得对可见正文盲目执行 URL 解码。
填写后核对空格、加号、标点与原文一致；若可见原文与档案不一致，以当前原商品正文为依据并记录差异。无法判断时记录具体位置，不凭猜测替换。

### 段落与换行

保留原商品描述中的段落、硬换行和空行，列表条目逐行填写；不要把文案合并成一段，也不要把屏幕宽度导致的自动折行当成原文换行。文字、标点和顺序不变。
富文本编辑器可能把一次性 `fill()` 或粘贴中的换行保存成普通空白。不能仅凭传入字符串包含 `\n`、`innerText` 相等或 DOM 快照分行，就判断排版正确。优先通过编辑器支持的输入方式逐段填写，用 Enter/Shift+Enter 建立实际段落或换行；具体按当前编辑器表现选择，不能用浏览器 evaluate 改 DOM 或内部状态。
填写后移开编辑焦点，并查看表单或可用预览的截图，确认段落和列表在页面上实际分行显示；截图存入本次记录。若仍挤成一段，重新按段输入并复查。排版未通过时不标记“待上架”。不要为验证排版点击发布；用户发布后若要求检查，再以商品详情页的实际显示为准。

价格、SKU及对应价格、品牌、成色、规格、运费照原商品的可见信息填入。不能把价格区间上下限自行映射给规格；缺失时再查看原商品可见选项。不要下单或提交订单。
库存不从闲鱼页面采集，也不把“现货”当作实际库存证据；发布表单库存统一填写 9999，并在执行记录中标记为展示库存策略，不代表真实库存。若平台不允许 9999，记录平台实际接受的上限或失败原因，不擅自改成其他数字。
商品位置按现有默认值保留，不核对；展示库存仍按前述要求填写 9999。
发货服务中的“24小时发货”必须保持关闭；若平台默认开启，关闭后重新检查并记录关闭状态。无法关闭或无法确认关闭时保留未上架并报告，不擅自更改其他服务承诺。
用户授权为指定商品准备闲鱼上架并上传商品图片时，按资料单顺序将对应商品的本地图片上传至该账号的发布表单；优先使用归档中已下载的页面图库图片，其次使用合适截图，不必在同一任务中重复询问已明确授权的上传。使用浏览器支持的文件上传接口，确认文件属于对应商品且可读；只上传 `watermark_check=passed` 的图片，跳过明显他人水印，不擦除水印。在执行记录中标明每张图片是 `screenshot` 还是 `original`，核对主图和顺序；上传失败或全部图片无法使用时保留未上架并记录缺口，不把无图表单标为完成。发布仍由用户手动操作。
原商品详情缺失、规格价格未明确或必填字段无法完成时，保持未上架，记录具体缺口并报告，不编造、不跳到后面的商品凑数。
访问原商品保持低频，页面跳转间隔至少约 12 秒；出现滑块/访问限制时停止平台采集，交由用户处理，不自动破解或反复重试。

## 完成回写

逐件核对可见表单：原文未改、原段落和换行在截图中实际呈现、规格价格一致、运费一致、图片上传完成。完成一件再改一件状态，不能先批量标记。
向本地 POST `/api/listing-queue` 发送 JSON（本地接口可用常规 HTTP 工具）：

```json
{"action":"status","product_id":"原商品ID","status":"待上架","preparation":{"publish_url":"实际发布页面URL","tab_id":"本会话实际标签页ID","prepared_at":"带时区时间","source_url":"原商品URL","images":["本地图片路径"],"notes":"必要的差异或待用户注意事项"}}
```

`publish_url` 只是发布入口，通常相同；**不能凭这个URL恢复尚未发布的表单**。保留已填标签页，报告每个商品对应标签页；若标签页丢失或页面刷新导致数据消失，先核实，需重填时将状态回退未上架，再准备。回退同一接口 status=未上架。
HTTP 失败时不要宣称回写成功；重读 GET 确认状态。不要直接覆盖队列文件。
交付时列出已填好数量、商品名称、未完成缺口，明确由用户在保留标签页点击发布，发布后手动标记已上架。

## 验收与恢复记录

每件在批次目录保存执行用的 listing.json、步骤记录 run.json、验收截图和本地图片路径。run.json 记录 product_id、资料版本、tab_id、publish_url、当前步骤、逐项验收结果、失败原因、更新时间。检查项至少包括：正文字符、真实段落空行、图片数量/顺序/主图、SKU名称价格、运费及服务选项。未检查不能记为通过。
资料分享使用 `share-packages/<product_id>/` 商品包；读取其中固定版本的 listing.json 和本地图片，不依赖发送方的浏览器标签页、localStorage 或登录状态。发布准备完成后仍需由用户在自己的闲鱼账号中审阅并点击发布。
资料完整度（待采集/待补齐/可上架）与队列状态独立，不能互相代替。第二个 skill 的可上架仅代表资料完整，第三个仍须验收表单。
恢复时先查队列状态及现存页面。已标记已上架不重复操作；待上架页面仍完整就复用；页面丢失或内容清空则回退未上架，按保存资料重建。不得把重复打开发布URL当成恢复了草稿，也不得为测试点击发布。
如果平台明确提供保存草稿功能，可在用户授权范围保存并记录草稿ID/URL；没有可见成功证据只能记为本地资料已保存。当前流程由用户点击发布、手动标记已上架。
完成一件并确认本地回写成功再处理下一件。失败项保留未上架并记录具体步骤，继续处理本批其余已选项；不取批次外商品替补。验证码或访问限制出现时停止平台操作并报告。
